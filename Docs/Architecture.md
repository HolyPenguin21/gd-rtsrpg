## 2. Базовые технологии и координаты

- **Unity 6 + URP**, 3D земля и 2D рисованные фэнтезийные спрайты в 3D-мире; **не пиксель-арт**.
- Камера ортографическая сверху под небольшим углом; реализована в Stage 01; ручная Unity-проверка пока NOT RUN.
- Конвенция координат: **XZ** — горизонтальная плоскость мира, **Y** — высота.
- Базовая реализация — простые MonoBehaviour и обычные типы данных по необходимости, без ECS, Jobs/Burst, service locator и инфраструктуры «про запас».
- Навигация наземная и **собственная**, без Unity NavMesh. Даже если модуль AI Navigation присутствует среди пакетов, в игровой логике он не используется.
- Не менять утверждённые решения, зависимости и ответственность модулей без отдельного согласования владельца.
- Числовые значения, которые ещё не утверждены (метры блока, zoom, speeds, budgets), задаются локально как конфигурация своей задачи и не объявляются постоянным глобальным контрактом.

## 4. Контракт террейна

1. Карта состоит из логических блоков с дискретными уровнями высоты. Между соседями создаётся непрерывная 3D-геометрия.
2. Перепады образуют уступы; проходимые изменения уровня — **рампы переменной ширины**.
3. На координату XZ имеется **одна** поверхность земли. Мосты/многоуровневая навигация не предусмотрены.
4. Рельеф не деформируется во время игры. Строительство по сетке только на ровных участках.
5. **Terrain Builder** строит поверхность по явно заданным данным. **Procedural Map** создаёт эти данные по seed, но не содержит второй версии построения меша.
6. Карта полностью генерируется при загрузке: логическая схема зон, стартовых мест, маршрутов и рамп; проверка связности; затем декоративный шум.

## 5. Контракт навигации и движения

1. Каждый блок земли делится на **4×4** навигационные подячейки. Ячейки — для планирования, фактическое движение плавное по мировым координатам.
2. Пехота — footprint **1×1**, большие юниты могут занимать 1×2/2×2 и другие формы, поворачиваемые с направлением; габариты важны при поиске и сглаживании маршрута.
3. **A*** по восьми соседям, без срезания заблокированных диагональных углов. Смена уровня высоты только по рампам. Вода/скалы/обрывы непроходимы.
4. Здания могут полностью перекрывать маршруты. Союзники используют мягкое избегание/уступание; противники могут сохранять линию обороны.
5. Группы получают общий маршрут/коридор и индивидуальные пути с конечными позициями; при недостатке места зона размещения расширяется.
6. **Move** находит обход или останавливается, не проталкивая вражеский строй. **Attack-Move** может атаковать блокирующих врагов или здания.
7. Repath — **по событиям**, с восстановлением при застревании и бюджетированием вычислений.
8. Navigation отвечает за путь, Movement — за фактическое движение, RTS Controls — за приказ, Combat — за боевое действие. **Никаких альтернативных реализаций одной ответственности.**

## 6. Контракт дальнего боя

- Возможность дальнего удара определяется **игровой дальностью/радиусом и боевыми условиями**, не физическим raycast по траектории.
- Визуальные снаряды (прямые или навесные) не определяют попадание.
- Союзные бойцы не закрывают линию огня; **friendly fire отсутствует**.
- Эти правила едины для игрока, AI и отображения атак.

### Stage 01: фактические правила

- Контроллер расположен прямо на Main Camera; отдельный rig/manager не нужен. `groundPosition` — точка обзора XZ на `planeHeight`. Положение камеры вычисляется из неё, высоты и фиксированного наклона, yaw=0. W/↑ = +Z (экран вверх), D/→ = +X (экран вправо).
- Экспоненциальный отклик скорости с точным интегралом за кадр и сглаживание size используют `Time.unscaledDeltaTime`. Отпускание клавиш немедленно обнуляет velocity; удержание MMB приоритетнее клавиатуры. При потере focus/disable сбрасывается drag baseline и velocity.
- Drag берёт два положения курсора, проецирует их одной текущей позой камеры и переносит reference на разность точек. Первый кадр удержания только запоминается. Нет зависимости от FPS/высоты/zoom через подобранный pixel multiplier.
- Bounds ограничивают только ground reference XZ, не frustum. Их можно выключить. Zoom target и текущий size ограничены отдельно; настройки min/max исправляются OnValidate.
- Player/Move и UI/Navigate уже содержат WASD/стрелки; UI/MiddleClick и UI/ScrollWheel — MMB/колесо. Они сохранены как template/UI. В сцене нет PlayerInput или EventSystem и нет читателей этих действий. Controller включает только свою копию Camera, поэтому конкурирующих обработчиков сейчас нет. Будущая UI-интеграция должна отдельно определить политику перехвата ввода.
- Числа камеры, размер/сетка контрольной плоскости — редактируемые значения для Stage 01, **не** размер блока или контракт будущей карты. Точка picking может быть за краями конечного Plane: математическая плоскость бесконечна.
- Ввод и pose применяются в LateUpdate; дальнейшим потребителям нужны текущая Camera и свежий вызов picking после обновления камеры, а не сохранённая координата прошлого кадра.
- Полная таблица Inspector-настроек и честный статус проверок: [Stage01Camera.md](Stage01Camera.md).

### Stage 02: фактические правила

- Рампа занимает прямоугольную полосу на нижнем блоке L длиной один блок; поднимается к соседу L+1. Позади требуется сосед L. Старт/ширина полосы дискретны по 4 подячейкам. Соседние уровни без рамп могут отличаться на несколько шагов — это отвесный уступ.
- Валидация отклоняет неверные размеры, длину данных, масштаб/переполнение координат, выходы, несовместимые уровни, наложения рамп, разрывы входа/выхода и пересекающиеся профили стыков. Данные не исправляются. CreateSurface бросает ArgumentException; Builder выводит понятное сообщение и удаляет устаревший mesh.
- Mesh и сведения о границах используют одни целочисленные профили TerrainSurface. Каждая общая грань обрабатывается один раз, равные профили не создают стенку. Боковина рампы с совпадающим концом сводится к треугольнику без вырожденной грани.
- Вершины на границах совпадают по координатам; нормали граней раздельные для резких уступов. Наружные стенки доходят до уровня на один шаг ниже минимума. Дно не строится.
- TerrainSurface возвращает локальные координаты mesh. В демо Transform = translation (-12,0,-10), rotation identity, scale (1,1,1). Для world point потребитель должен применить TransformPoint; сведения о поверхности не являются screen picking.
- Камера и Input не менялись. Plane отключён и showCursorMarker=false; математическая проекция Y=planeHeight остаётся прежней, в том числе для MMB drag. Настоящий terrain picking не реализован.
- Детали формата, ограничений и ручной проверки: [Stage02Terrain.md](Stage02Terrain.md). Stage 02 реализован в исходниках, не принят; Unity проверки NOT RUN.

## 8. Контроль изменений, качества и архитектуры

- В задаче описываются только текущий Stage и необходимые интеграции. Любой модуль следует проверить снизу вверх: данные → алгоритм/класс → scene references, GUID/.meta → команды/события → соседние модули.
- При пересечении границ сначала представить **минимальное архитектурное предложение** владельцу и обновить этот контракт после одобрения.
- Не вводить автоматизированные Unit/Integration/PlayMode тесты, фикстуры и тестовую инфраструктуру до отдельного решения владельца.
- При наличии Unity делать короткие проверки открытия сцены, компиляции и Play Mode. Если Unity недоступна, явно указывать **NOT RUN** и проводить доступную статическую проверку.
