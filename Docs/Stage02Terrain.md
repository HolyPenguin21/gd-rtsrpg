# Stage 02 — Terrain Builder

Issue #4 принят и объединён в PR #5. Ниже актуальный контракт с доработками Issue #6 (Stage 03, приёмка открыта). Stage 01 принят и объединён в PR #3. Unity 6000.5.4f1 / URP 17.5.0; новые пакеты не добавлены.

## Формат входа и координаты

`TerrainMapData` — отдельный ScriptableObject (Create → GameDev → Terrain Map). Inspector содержит `width`, `length`, `blockWorldSize`, `heightStepWorld`, массив `levels` длиной width×length и массив `ramps`. Уровень блока: `levels[x + z * width]`; отрицательные уровни допустимы. XZ — горизонталь, +Y — вверх. Scale должны быть конечными положительными числами; значения демо не являются игровым стандартом.

Каждый блок делится на 4×4 области размером blockWorldSize/4. `CreateSurface()` валидирует данные без изменения asset и возвращает отдельный неизменяемый `TerrainSurface`. Он содержит 16 `Cell` на блок: `Level` — исходный нижний уровень, `RampIndex` (-1 для плоскости), `Uphill`, высоты углов `Corner(0/1, 0/1)` в целочисленных четвертях уровня. У рампы верхний уровень равен Level+1. Углы однозначно задают плоскость каждой области. Ввод не зависит от созданного mesh.

`GetCell`, `GetEdge`, `IsBoundaryBlocked` работают с координатами **подъячеек**, не блоков. North=+Z, East=+X, South=-Z, West=-X. Профиль края всегда направлен по +X для N/S или +Z для E/W. Граница непроходима геометрически, если за ней край карты либо профили двух сторон различаются хотя бы в одном конце. Совпадение только одного угла не открывает переход. Это статическая геометрическая информация: здесь нет graph, A*, диагональных правил, footprint, занятости или перемещения.

`Position(latticeX, latticeZ, quarterLevel)` возвращает **локальную** позицию mesh. World point = `builder.transform.TransformPoint(...)`. В демо заданы только смещение и единичный масштаб; при изменении масштаба Transform реальные мировые размеры тоже изменятся. Для изменения размера блока следует редактировать данные карты.

## Рампы

Каждая `TerrainRamp` содержит:

| Поле | Значение |
|---|---|
| `block` | Нижний блок L, X/Z (Vector2Int.y означает Z) |
| `uphill` | North=0, East=1, South=2, West=3 |
| `startSubcell` | Начало поперечной полосы 0..3 |
| `widthSubcells` | Ширина 1..4; start+width ≤ 4 |
| `cutIntoCliff` | false (legacy): вне полосы L; true: каменные плечи на L+1 внутри блока |

Рампа заменяет поверхность полосы нижнего блока по всей его длине и линейно повышается от L до L+1. Поперечная ось — X для North/South, Z для East/West; индексы всегда идут от меньшей координаты, **не зеркалятся** при смене направления. При cutIntoCliff=true вне полосы плоский L+1, отражённый в TerrainSurface.Cell; false сохраняет прежний L. Для ширины 4 боковые плечи задаются соседними верхними блоками. Одно определение cliff-cut владеет целым блоком; в legacy-режиме непересекающиеся полосы могут делить блок.

Сосед в направлении uphill должен быть L+1; сосед сзади — L. Оба должны существовать. После наложения всех определений фактические входные/выходные профили каждой рампы обязаны совпадать с продолжением. Рампы могут делить один блок только без пересечения полос; конфликт/пересечение областей, обрыв входа/выхода или пересекающиеся по высоте боковые профили отклоняются. Несколько последовательных подъёмов допустимы только при непрерывных стыках. Уклон определяется отношением heightStepWorld/blockWorldSize; максимальный игровой уклон ещё не утверждён.

Неверные размеры, масштаб, длина массива высот, диапазоны/ориентация рамп, уровни и стыки вызывают `ArgumentException` с местом ошибки. Builder пишет сообщение в Console, очищает старый mesh и Surface. Исходные данные не исправляются молча.

## Построение и жизненный цикл

`TerrainBuilder` на одном GameObject с MeshFilter/MeshRenderer вызывает Rebuild в OnEnable (при запуске сцены), либо по явному вызову/Context Menu → Rebuild Terrain. Нет ExecuteAlways, Update или автоматической перестройки при редактировании Inspector: после правки входа нужно вызвать Rebuild либо перезапустить Play Mode. До первого запуска/явного Rebuild mesh в сцене отсутствует.

Builder создаёт один Mesh с submeshes grass/cliff/ramp, один верх на подячейку и гранёные скальные стенки там, где различаются профили. Центр стены смещён внутрь скалы, четыре ребра стыков неизменны; соседние сегменты не расходятся. Каждый общий край обрабатывается один раз. Соседи одной высоты не получают внутреннюю стенку; совпадающие точки вычисляются из общей целочисленной решётки. Вершины граней имеют раздельные нормали для резких уступов. Конец боковины рампы превращается в треугольник, вырожденные треугольники пропускаются. Край карты закрывается стенкой до уровня min(levels)-1; дно не строится. Никаких коллайдеров и второго верхнего слоя.

Builder освобождает свой Mesh при Rebuild/disable/destroy; использует Destroy в Play Mode и DestroyImmediate вне его. Результат помечен DontSave, не записывается в scene/asset. `BuildMesh(surface)` доступен как явный алгоритм; прямой вызывающий обязан уничтожить возвращённый Mesh.

Stage 03 использует `TerrainSurface.shader` и три материала: TerrainPreview (grass, прежний GUID), Cliff, Ramp. Тип задаёт Builder, мировой 3D grain устойчив к масштабу и не требует UV. Сетка preview больше не рисуется. Camera Preview shader и старые camera-материалы не менялись.

## Явное демо

`Assets/Scenes/SampleScene.unity` → **Terrain (explicit or seeded)** → `Assets/Terrain/DemoTerrain.asset`.

- 6×5 блоков; blockWorldSize=4, heightStepWorld=2 (демонстрационные значения).
- Z=0: 0,0,0,0,0,0; Z=1: 1,0,1,0,1,1; Z=2: 1,1,1,1,1,1; Z=3: 2,2,1,2,2,2; Z=4: 2,2,2,2,2,2. Изменённые плоские блоки образуют плечи проходов; все три рампы cutIntoCliff=true.
- Рампа (1,1), North, start=1, width=1: полоса local X=5..6, Z=4..8, Y=0..2.
- Рампа (3,1), North, start=0, width=4: local X=12..16, Z=4..8, Y=0..2.
- Рампа (2,3), North, start=0, width=3: local X=8..11, Z=12..16, Y=2..4.
- Transform terrain: (-12,0,-10), rotation identity, scale (1,1,1). Карта занимает world X=-12..12, Z=-10..10.

Между рампами остаются отвесные уступы. Соседние блоки в каждом ряду показывают бесшовную плоскость. Код камеры Stage 01, Input Actions, URP и прежние GUID сохранены. Demo tilt=55°, initialZoom=15. Старый Camera Reference Plane отключён; `showCursorMarker=false`. Проекция курсора всё ещё пересекает бесконечную плоскость Y=planeHeight, включая MMB drag. Она **не является попаданием в высотный terrain**. Реальный terrain picking остаётся отдельной задачей.

## Ручная проверка и фактический статус

Статически проверены данные демо, формулы четырёх ориентаций, единый источник углов/стыков, порядок граней, обработка сужающихся боковин, lifetime mesh и ссылки scene → builder/map/material → script/shader. Вход одинаково обходится Z→X, без Random и обновления по кадрам. Camera scripts и Input Actions не изменены; Packages/ProjectSettings не изменены. Это аудит исходников, не запуск Unity.

| Проверка | Статус в среде реализации |
|---|---|
| Unity import и C# compilation | **NOT RUN** — Unity/C# compiler не установлен |
| Shader compilation / URP rendering | **NOT RUN** |
| Открытие SampleScene | **NOT RUN** |
| Play Mode, визуальные стыки/камера, повторные запуски | **NOT RUN** |

Процедура для менеджера/владельца в Unity:

1. Открыть существующий проект и SampleScene; дождаться импорта без ошибок C#/shader. Запустить Play Mode: один terrain mesh, Plane/маркер выключены, камера видит поле.
2. Осмотреть плоскости, уступы и рампы 1/3/4 подячейки на разных zoom. Проверить примыкания снизу/сверху и боковины без дыр, мерцания или наклонных проходов вне рамп. При необходимости Scene View позволяет осмотреть обратную сторону.
3. Проверить WASD/стрелки, MMB и scroll. Маркер не появляется; drag остаётся относительно Y=0.
4. Изменить в копии карты blockWorldSize/heightStepWorld; явно Rebuild. Проверить те же ширины в подячейках, новые физические размеры, отсутствие дублированной поверхности.
5. В копии карты развернуть/переставить рампы на East/South/West с подходящими нижними и верхними соседями; проверить каждый вход/выход и боковой стык. Демо исходно показывает North.
6. По одному испортить длину levels, размеры/scale, width/start, направление/координаты, верхний/нижний уровень, перекрыть рампы. Rebuild должен сообщать ошибку, не оставлять старый mesh и не менять введённые данные. Вернуть корректный asset.
7. Повторить Rebuild, disable/enable объекта и Play/Stop несколько раз: старые generated Mesh освобождаются, число объектов не растёт. После повторного построения той же карты геометрия совпадает.

Stage 03 добавляет seed-вход в тот же Builder; см. [Stage03ProceduralMap.md](Stage03ProceduralMap.md). Navigation, юниты, terrain picking и автотесты не реализованы. Для N/E/S/W теперь есть Context Menu → Show Four Ramp Directions; ручной игровой визуальный контроль всё ещё NOT RUN.
