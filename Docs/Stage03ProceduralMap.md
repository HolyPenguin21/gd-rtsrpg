# Stage 03 — Procedural Map и читаемый террейн

Issue #6. Реализация для менеджерского аудита; **визуальная приёмка открыта**. Base main: `59e65c5bd24f8e0b84887b3a2319a76c8afb403f` (PR #5). Новых пакетов, автотестов и систем следующего этапа нет.

## Видимый результат и источники данных

Один TerrainBuilder в SampleScene умеет показывать три источника: Explicit, DirectionReview, Procedural. Стартовое состояние — прежняя явная карта 6×5. При запуске OnEnable строит mesh; вне Play Mode можно явно вызвать Context Menu → Rebuild Terrain. Перестроения из Update/OnValidate нет. Inspector-правки требуют Rebuild.

Контекстные действия компонента:

| Действие | Результат |
|---|---|
| Show Explicit 6x5 | DemoTerrain, прежние размеры и проходы 1/4/3 |
| Show Four Ramp Directions | RampDirections 9×9: North/South ширина 4, East ширина 1, West ширина 3 |
| Show Procedural Seed 104729 | Первый пример; сбрасывает Procedural settings на демонстрационные значения |
| Show Procedural Seed 130363 | Второй пример с другой разметкой проходов/уступов; те же демонстрационные настройки |
| Rebuild Terrain | Текущий Source и текущие настройки, без сброса |

Terrain Transform сохранён (-12,0,-10), rotation identity, scale 1. Поэтому 10×10 процедурный пример занимает world X=-12..28, Z=-10..30. Панорамирование камеры позволяет осмотреть дальние зоны; её bounds ограничивают reference point, а не frustum. Камера по-прежнему ортографическая, MMB/WASD/scroll прежние; менялись только демонстрационные tilt=55° и initialZoom=15. Движение камеры и математический plane picking не читают TerrainSurface; маркер выключен.

## A–C: рампы, скалы и покрытия

`TerrainRamp.cutIntoCliff` — минимальное расширение сериализованных данных. Отсутствующее поле остаётся false и сохраняет старый raised-strip контракт. True поднимает плоскую часть блока вокруг полосы до L+1. Это настоящие Cell уровня L+1, а не визуальное перекрытие рампы. Ширина 1..4, полоса и линейный уклон остаются прежними. Один cliff-cut занимает целый блок; конфликт определений отклоняется. Общий валидатор также требует две плоские боковые стенки на L+1: при ширине 4 их задают соседние блоки. Поэтому ни одна проверенная cliff-cut рампа не остаётся приподнятой полосой без плеч.

DemoTerrain мигрирован **с сохранением GUID, 6×5, всех трёх позиций/ширин и высот входа/выхода**: изменены только плоские блоки плеч, все рампы включают cutIntoCliff. Дополнительный RampDirections даёт четыре направления вокруг центрального плато; дальняя рампа South расположена отдельно от ближней North.

Стенки строит прежний Wall. Четыре края сегмента фиксированы, детерминированный центр смещается внутрь скалы и меняет положение по высоте/длине. Четыре неплоских треугольника с раздельными нормалями создают каменные грани. Выемка не выступает на нижнюю плоскость или в проход. Общие вертикальные/горизонтальные рёбра не расходятся, концы рампы могут сходиться в треугольник. Силуэт внутри одного блока сохраняет дискретную верхнюю линию; природную ступенчатость общего контура дают плечи и неровная разметка границы террас. Нет геометрического шума на плоских верхах/полотне рампы, меняющего проходимость.

Mesh имеет три submesh: **0 grass, 1 cliff, 2 ramp**. Все три материала назначены в сцене и при Rebuild. Один MeshRenderer, без объектов на каждую клетку. TerrainPreview сохраняет GUID, но использует новый `GameDev/Terrain Surface` shader; старый Camera Preview shader не менялся. Grass — приглушённый зелёный/земля; Cliff — серо-коричневый камень; Ramp — светлая утоптанная земля/гравий. Переходы совпадают с точными краями проходимой полосы, без бордюра поверх прохода.

Shader получает тип только через слот материала. 3D world-space noise непрерывен по координатам, не растягивается на высокой стене; мелкое зерно сглаживается производными при удалении камеры. Main Light + SH и геометрические нормали дают контраст граней. Динамические тени, normal maps и художественные текстуры пока не добавлены.

**Порядок работы:** A–C изменены и просмотрены по исходникам до D. Ручной игровой визуальный контроль на этом промежуточном шаге **NOT RUN**, Unity недоступна. Это не свидетельство визуальной приёмки; её требуется выполнить по процедуре ниже.

## D: параметры и ограниченная генерация

| Inspector / API | Значение и ограничения |
|---|---|
| seed | Любой int; presets 104729 и 130363 |
| width / length | 8..48 блоков; default 10×10, ограничение локально для этого простого генератора |
| blockWorldSize / heightStepWorld | Конечные положительные; default 4 / 2, общий валидатор TerrainMapData |
| uphill | N/E/S/W; default North; координаты зон должны соответствовать направлению |
| terraceCount | 1..4 перехода уровня; задаёт число уступов/высоту верхней зоны; default 2 |
| rampsPerTerrace | 1..число доступных внутренних полос с шагом 3 блока; default 1 |
| rampWidth | 3 или 4; default 4; ширина 1 поддержана явными картами |
| edgeVariation | 0..1, вероятность сдвига незарезервированной колонки границы на один блок; default 0.65 |
| startZone / goalZone | Точные плоские блоки; default (1,1) / (8,8), нижняя и верхняя зоны |
| keyZones | Дополнительные обязательные плоские блоки; могут лежать на промежуточной террасе |

Генератор:

1. Проверяет размер/параметры и фиксирует ключевые блоки. Размеры для генерации ограничены до выделения массивов.
2. Размещает террасы между start и goal вдоль uphill. Требуется uphill-разница координат **не меньше 3×terraceCount+1**: место для плоских входов между проходами. Поперечное положение зон свободно.
3. Выбирает разнесённые широкие проходы и высокие боковые блоки плеч. Дополнительный запас длины распределяется локальным xorshift32; расположение проходов также зависит от seed. Входы/выходы и ключевые зоны не затираются шумом.
4. Передаёт временные levels/ramps общей статической фабрике `TerrainMapData.CreateSurface`; это та же валидация, что у authored asset. Flood fill по четырём совпадающим профилям проверяет достижимость всех 16 клеток каждого ключевого блока и его плоскостность.
5. Варьирует только незарезервированные колонки уступа; не трогает проход, соседние плечи или поперечные колонки ключей. Повторяет общую валидацию и связность. DetailSeed передаётся Surface для каменных граней.

Нет случайного глобального UnityEngine.Random, бесконечных retries, изменения общего ScriptableObject, альтернативного валидатора terrain или второго mesh-builder. Генерация состоит из **одного ограниченного прохода**; несовместимые зоны, слишком много переходов/рамп, конфликт key с рампой, отсутствие связности и неверная геометрия дают явный ArgumentException. Builder удаляет устаревший результат и выводит диагностику в Console. Менять seed/настройки нужно явно, скрытых исправлений нет.

Четырёхсвязный flood fill — только проверка обязательных зон при загрузке. Он не выдаёт маршрут, не моделирует footprint/занятость и не подменяет Stage 04 Navigation. Текущий генератор намеренно создаёт направленные террасы; сложные биомы/реки/острова/эрозия не реализованы.

## Ручная приёмка

1. Открыть проект Unity 6000.5.4f1, SampleScene; дождаться импорта C#/shader без Console errors. В Play Mode проверить явную 6×5. Вход, полотно, выход и два каменных плеча должны читаться без выделения объекта. Сверить ширины 1/3/4 с TerrainSurface, отсутствие наклонных ложных проходов.
2. Показать Four Ramp Directions. Осмотреть N/E/S/W при size примерно 10 и 20, включая дальнюю South рампу. Проверить ступеньки плеч, концы, стыки и отсутствие дыр/мерцания. Для обратного ракурса пользоваться Scene View / Align View to Selected camera pose на временной копии камеры: runtime controller сохраняет yaw=0 и не предоставляет orbit. Не менять код камеры ради проверки.
3. Сохранить в PR **реальные Game View скриншоты** двух масштабов и минимум двух направлений обзора. Для обратного Game View ракурса временно отключить controller и развернуть камеру на 180° вокруг центра terrain; после проверки восстановить сцену. Проверить средний и дальний zoom; не выдавать Scene View/псевдорендер за Game View.
4. Поочерёдно вызвать оба seed preset. Сравнить проходы и ступенчатые уступы; повторить тот же preset/Rebuild: уровни, рампы, грани должны совпадать. Проверить camera pan/MMB/zoom, включение/выключение terrain и Play/Stop — mesh не должен накапливаться.
5. В Inspector Procedural установить East и те же старт/цель; затем South с start=(1,8), goal=(8,1); West со start=(8,1), goal=(1,8). Rebuild. Проверить входы/выходы со всех направлений. Вернуть default North.
6. Проверить размер 16×16, terraceCount=3, goal=(14,14), rampsPerTerrace=2, rampWidth=3, несколько seed. Затем один раз неверный размер, слишком близкий goal, rampWidth=2, seed/ключ с конфликтом. Должна быть ограниченная понятная ошибка и пустой результат; исходный asset не меняется.
7. Вернуть Explicit и настройки сцены перед сохранением. Навигация и terrain picking не входят в эту приёмку.
